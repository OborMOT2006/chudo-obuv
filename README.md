# Чудо Обувь — система оформления заказов

Готовый учебный проект для практики к ДЭ‑2027, 09.02.07 «Информационные системы и программирование» (Программист).

**Технологии:** Python 3.8+, PyQt5, PostgreSQL 12+, psycopg2, openpyxl, pandas (аналитика). **Кодировка:** UTF‑8. Приложение работает локально, без браузера и интернета после установки зависимостей.

## Возможности

- Каталог обуви из PostgreSQL: изображения, категория, производство, название, состав, суммарный остаток, цена.
- Заглушка `picture.png` при отсутствии фотографии.
- Подсветка товаров с суммарным остатком **≤ 3** цветом `#FF8080`.
- Скидка **25%** на модели, по которым не было заказов **за предыдущий календарный месяц**, относительно текущей даты. Сохранение цены на момент заказа.
- Вход по логину, без пароля; гостевой просмотр каталога.
- У авторизованного пользователя — поиск по имени/описанию, фильтр «Все категории», сортировка по цене, карточка товара, размер, количество, корзина, оформление заказа.
- Менеджер и администратор — список заказов с ФИО, датой и суммой, просмотр состава, создание заказа для выбранного клиента, удаление заказа с подтверждением.
- Только администратор — смена даты и удаление отдельных позиций заказа.
- Подтверждение и обработка ошибок; транзакции, контроль остатков при параллельной работе, автоматическое обновление каталога и заказов после изменений.
- Аналитический скрипт модуля 5 (требуются отдельные CSV Приложения 4).

## 1. Установка на MOS Linux / ROSA

Откройте терминал. Если перед приглашением есть `(.venv)`, сначала введите `deactivate`. **Для DNF виртуальное окружение не нужно.**

```bash
cd ~
sudo dnf install -y postgresql-server postgresql-contrib python3 python3-pip git dbeaver libreoffice vscode
```

В ROSA 2021.1 служба обычно `postgresql12`, но название может отличаться. Инициализация требуется только при первой установке; не запускайте `initdb` поверх действующей БД:

```bash
sudo systemctl enable --now postgresql12
cd /tmp
sudo -u postgres psql -c "SELECT version();"
```

Если изначально служба не стартует из-за `Отказано в доступе: /var/log/postgres/postgresql`, исправьте эту **конкретную** ошибку:

```bash
sudo mkdir -p /var/log/postgres
sudo touch /var/log/postgres/postgresql
sudo chown postgres:postgres /var/log/postgres
sudo chown postgres:postgres /var/log/postgres/postgresql
sudo chmod 664 /var/log/postgres/postgresql
sudo systemctl restart postgresql12
```

Для работы через TCP задайте пароль postgres (дважды вводится невидимый пароль):

```bash
cd /tmp
sudo -u postgres psql
```

В консоли psql:

```text
\password postgres
\q
```

**DBeaver:** новое подключение → PostgreSQL → host `127.0.0.1`, порт `5432`, БД `shoe_store` (после создания), пользователь `postgres`, введённый пароль. При первом подключении DBeaver может потребовать JDBC-драйвер. Скачайте его в подготовительный день при наличии интернета или используйте предоставленный локальный `.jar`.

## 3. Создание и заполнение PostgreSQL

**ВНИМАНИЕ: `db/schema.sql` удаляет существующие таблицы проекта. Не повторяйте эти команды на БД с полезными изменениями!**

Один раз создайте БД:

```bash
sudo -u postgres createdb shoe_store
```

Если пишет `already exists`, существующую БД не удаляйте. В пустой учебной базе выполните:

```bash
cd ~/Chudo_Obuv_GitHub
sudo -u postgres psql -v ON_ERROR_STOP=1 -d shoe_store < db/schema.sql
sudo -u postgres psql -v ON_ERROR_STOP=1 -d shoe_store < db/data.sql
sudo -u postgres psql -d shoe_store -c "SELECT COUNT(*) FROM products;"
```

Ожидается **34 модели, 92 товарные позиции, 20 пользователей, 10 заказов, 30 строк состава заказа.** Три модели есть только в Stock/Orders; для них взяты только известные из исходников сведения, отсутствующие поля оставлены пустыми. Размер `36.5` хранится как `NUMERIC(4,1)`, а не округляется до целого.

`db/data.sql` уже создан из оригинальных Excel; **его не нужно вручную импортировать через DBeaver**. Для пересборки при изменении XLSX:

```bash
source .venv/bin/activate
python scripts/build_data_sql.py
```

Для загрузки через Python в предварительно созданную *пустую* схему вместо `db/data.sql` допускается `python -m db.import_data`. Не запускайте оба варианта подряд — будут дубли.

```bash
cd ~/Chudo_Obuv_GitHub

```

Либо, если `.venv` активно:

```bash
source ./config_local.sh
python main.py
```

При ошибке подключения проверьте службу `postgresql12`, пароль и имя БД. Для редактирования исходного кода:

```bash
cd ~/Chudo_Obuv_GitHub
code .
```

## 5. Тестовые пользователи и сценарий проверки

| Роль | Логин | Что проверить |
|---|---|---|
| Гость | Кнопка «Продолжить без входа» | Просмотр каталога |
| Администратор | `isivanov` | Создание, просмотр, удаление и редактирование заказов |
| Менеджер | `papetrov` | Работа с заказами без редактирования |
| Авторизованный | `asidorova` | Поиск, карточка, корзина, оформление |

Проверка полного сценария: войти клиентом → выбрать модель → выбрать доступный размер → добавить в корзину → при необходимости изменить количество → подтвердить → каталог обновится. Затем войти менеджером → «Заказы» → просмотреть заказ → добавить заказ для другого пользователя или удалить существующий. Администратор дополнительно меняет дату и удаляет позиции.

**Примечание:** обучение проводится по демонстрационному кейсу. В реальной системе вход без пароля небезопасен, но здесь это прямое требование КИМ.

## 6. Модуль 5 — CSV-аналитика

Файлы **`Sessions_analytics.csv`, `Orders_analytics.csv`, `Order_items_analytics.csv`, `Shoe_models_analytics.csv`** относятся к отдельному Приложению 4. Их не было в предоставленном архиве. Код расчётов есть, но готовые численные ответы получить без этих файлов нельзя.

Сохраните четыре CSV в одну папку, например `analytics/csv/` (создайте её), затем:

```bash
cd ~/Chudo_Obuv_GitHub
source .venv/bin/activate
python analytics/run_analytics.py analytics/csv
```

Если реальные заголовки CSV отличаются, поправьте соответствия названий в функции `prepared()`; скрипт сообщит недостающие поля.
